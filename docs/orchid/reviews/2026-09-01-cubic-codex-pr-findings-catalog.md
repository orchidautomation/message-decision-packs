- The highest-volume hotspots are README ownership/refresh, transactional authoring and temporary-workspace safety, MCP path/lifecycle security, and CLI schema/capability parity.

## What counts as a finding

This catalog includes every inline review comment authored by `chatgpt-codex-connector[bot]` or `cubic-dev-ai[bot]` in the audit window. It records priority, location, reviewer explanation, source URL, and GitHub thread state. Top-level clean-review, task-summary, duplicate-review, and failed-review comments are logged separately and are not included in the 208-finding total.

GitHub marks a comment **outdated** when its diff location no longer matches the PR head. That status says nothing by itself about whether the underlying bug was fixed. Each remediation item therefore starts in **needs current-main verification** unless a dedicated regression test proves otherwise.

## Remediation strategy

Do not open 202 independent patches. Triage and fix by shared invariant:

1. **Build the verification ledger.** Reproduce all 53 P1 findings against current `main`, then the 94 unresolved/current-location findings. Mark each `confirmed`, `already fixed with test`, `superseded`, or `false positive`, and link proof.
2. **Wave A — filesystem and publication safety.** Batch PRs #212, #220, #222, and #223 around symlink/ancestor validation, staging cleanup, rollback preservation, atomic publication, README ownership boundaries, and temporary-workspace containment.
3. **Wave B — MCP and provider boundary.** Batch PRs #214, #219, and #229 around approved-root enforcement, descriptor/snapshot handoff, output reservation, cancellation, concurrency, and provider-consent binding.
4. **Wave C — CLI contract parity.** Batch PRs #211, #218, #225, #227, #231, #232, and #263 around one-source-of-truth capabilities, JSON/help behavior, readiness/doctor schemas, diagnostics, recovery claims, and route-budget summaries.
5. **Wave D — release and installer correctness.** Batch PRs #221, #224, #234, and #235 around version parity, release assets, aggregate installer preflight, and custom `CODEX_HOME` behavior.
6. **Wave E — skill/docs/eval integrity.** Batch PRs #213, #217, #226, #228, #230, #233, and #264 around public/private boundaries, portable prerequisites, progressive disclosure, eval isolation, category coverage, and stale links/version claims.
7. **Close with regression proof.** Every confirmed finding gets a focused failing test before the fix where practical. Run affected suites per wave, then one full CI pass at the exact final commit. Only then resolve the original GitHub thread and record the proof.

Recommended order: Wave A and Wave B first because they contain filesystem/security P1s; Wave C next because contract drift can silently mislead agents; Waves D and E follow.

### [PR #212: MDP-243: make mdp init transactional](https://github.com/orchidautomation/message-decision-packs/pull/212)

1. **P1 · Codex · resolved; current diff** — [Reject symlinked ancestor directories during preflight](https://github.com/orchidautomation/message-decision-packs/pull/212#discussion_r3864851416) at `cli/src/commands/init_transaction.rs:157`
   - Reviewer explanation: When an existing destination contains a symlinked generated directory, such as `root/examples -> /other/path`, checking only `symlink_metadata` on each final artifact does not detect that ancestor. The merge then follows the symlink and publishes `clay-row.json` and `decision-input-scenarios.json` outside the requested root while reporting success. Preflight every required ancestor with `symlink_metadata` and reject symlinks before staging or publication.
2. **P1 · Codex · resolved; current diff** — [Preserve recovery backups when rollback fails](https://github.com/orchidautomation/message-decision-packs/pull/212#discussion_r3864851423) at `cli/src/commands/init.rs:1078`
   - Reviewer explanation: If publication fails after existing files have been moved and `merge_into_existing_root` cannot restore one of them, it returns early with the backup directory as the remaining recovery source. This unconditional cleanup then recursively deletes that backup, losing the original file while the caller reports `init not published`. Rollback failures must retain the backup and be reported as indeterminate with its recovery path.
3. **P1 · Codex · unresolved; current diff** — [Normalize empty relative parents before checking devices](https://github.com/orchidautomation/message-decision-packs/pull/212#discussion_r3865208731) at `cli/src/commands/init_transaction.rs:247`
   - Reviewer explanation: When a fresh destination is a single-component relative path such as `mdp init --dir pack`, `destination.parent()` is the empty path rather than `None`. This branch passes that empty path to `ensure_same_filesystem`, where `fs::metadata("")` fails, so initialization reports a publication failure instead of performing the rename. Normalize an empty parent to `.` before staging and filesystem checks.
4. **P2 · Codex · resolved; current diff** — [Include required empty directories in the transaction](https://github.com/orchidautomation/message-decision-packs/pull/212#discussion_r3864851436) at `cli/src/commands/init.rs:503`
   - Reviewer explanation: Required empty directories are created only after publication, so an absent-root rename exposes an incomplete tree and any subsequent `create_dir_all` failure leaves a published pack even though `init` returns an error. Additionally, on an existing root where `.mdp/briefs` is a regular file, `exists()` is true and initialization reports success while leaving the non-directory in place. Represent these directories in staging/preflight and validate their node types before publication.
5. **P2 · Codex · unresolved; current diff** — [Clean partial staging trees when staging fails](https://github.com/orchidautomation/message-decision-packs/pull/212#discussion_r3865208738) at `cli/src/commands/init.rs:1065`
   - Reviewer explanation: If any `create_dir_all` or `fs::write` fails after `stage_artifacts` has created part of the nonce-named tree—for example because the filesystem fills during staging—the `?` returns directly and bypasses every cleanup path below. This leaves incomplete `.mdp.init.staging.*` data beside the destination and also omits the promised not-published context; clean the staging path inside `stage_artifacts` on error or wrap this call with cleanup.

### [PR #214: MDP-246: Enforce MCP approved roots and per-call provider consent](https://github.com/orchidautomation/message-decision-packs/pull/214)

1. **P1 · Codex · unresolved; current diff** — [Validate the request prompt against approved input roots](https://github.com/orchidautomation/message-decision-packs/pull/214#discussion_r3866351039) at `scripts/mdp-run-mcp-server.mjs:487`
   - Reviewer explanation: When a generative `mdp.run-request.v1` contains its normal separate `prompt` artifact, this code freezes only `parsed.inputs`. The CLI later stages `request.prompt.source_path` independently in `run_runtime.rs::execute_transaction`, so a crafted request can make the child read a valid prompt file outside `MDP_MCP_INPUT_ROOTS`; that file is also absent from `sourceSha256s`, allowing its contents to reach the provider without the adapter approving or digest-binding them. Freeze and bind `parsed.prompt.source_path` alongside the other inputs.
2. **P1 · Codex · unresolved; current diff** — [Pass frozen bytes to children instead of reopening paths](https://github.com/orchidautomation/message-decision-packs/pull/214#discussion_r3866351045) at `scripts/lib/mcp-path-policy.mjs:99`
   - Reviewer explanation: When a source or approval file is modified in place after `freeze()` but before the child reads it, its device and inode remain unchanged, so this final check accepts it. Both the proposal runner and Rust run runtime subsequently reopen the original pathname, meaning a provider-capable invocation can consume modified bytes while consent remains bound to the earlier SHA-256. Rechecking metadata cannot close the post-check spawn race; the child needs a private copy created from the frozen bytes or an equivalent descriptor-backed handoff.
3. **P1 · Codex · unresolved; current diff** — [Reserve outputs through the validated parent descriptor](https://github.com/orchidautomation/message-decision-packs/pull/214#discussion_r3866351053) at `scripts/lib/mcp-path-policy.mjs:78`
   - Reviewer explanation: If a writable approved output/work parent is renamed and replaced with a symlink after this method returns but before the child creates the leaf, the returned plain pathname is resolved through the replacement and the child can write outside the approved root. `newOutput()` closes the checked parent descriptor and performs neither exclusive creation nor a descriptor-relative reservation, so the final checks in both MCP servers leave a TOCTOU window. Creation must be anchored to the validated parent object rather than deferred to a later pathname lookup.
